# Контрольные вопросы
 
### 1. Что такое DOM и чем он отличается от исходного HTML-кода страницы?
 
DOM — это дерево объектов в памяти браузера, которое он строит из HTML. Каждый тег, текст и комментарий становится объектом.
 
HTML — это просто текст файла. DOM можно менять из JavaScript, и страница перерисуется. Вкладка Elements показывает DOM, а не исходный код.
 
### 2. Почему у `<ul>` с тремя `<li>` свойство childNodes.length больше трёх?
 
В childNodes входят все узлы, в том числе текстовые: переносы строк и отступы между тегами. Поэтому узлов 7, а элементов 3.
 
Только элементы даёт свойство children.
 
### 3. Чем живая коллекция отличается от статической? Какие методы возвращают какую?
 
Живая коллекция сама обновляется при изменении DOM, статическая — это снимок на момент вызова.
 
- Живая (HTMLCollection): getElementsByTagName, getElementsByClassName.
- Статическая (NodeList): querySelectorAll.
### 4. Чем textContent отличается от innerHTML? Что такое XSS?
 
textContent записывает и читает только текст, теги показываются как обычные символы. innerHTML разбирает строку как HTML и создаёт элементы.
 
XSS — это внедрение чужого кода на страницу через данные пользователя (например, `<img onerror=...>` в innerHTML). Данные пользователя нужно вставлять через textContent.
 
### 5. Чем атрибут href отличается от свойства href?
 
Атрибут хранит то, что написано в HTML (`#catalog`). Свойство содержит полный адрес, который вычислил браузер (`http://.../index.html#catalog`).
 
### 6. Почему append уже вставленного элемента перемещает его, а не копирует?
 
Один объект узла может находиться в дереве только в одном месте. Для копии нужно использовать `cloneNode(true)`.
 
### 7. Зачем нужен DocumentFragment?
 
Это лёгкий контейнер вне страницы. В него собирают много элементов и вставляют одним вызовом. Фрагмент «растворяется», в дерево попадает только его содержимое, а браузер пересчитывает страницу один раз.
 
### 8. Почему управлять оформлением лучше через classList, чем через style?
 
При использовании classList оформление остаётся в CSS, а JavaScript только переключает состояние (add, remove, toggle). Это проще менять и читать, чем набор inline-стилей.
 
### 9. Что означает формула UI = f(state)? Какую проблему она решает?
 
Интерфейс — это функция от состояния: страница вычисляется из данных. Данные хранятся в одном месте, а любое действие меняет их и вызывает render.
 
Это решает проблему рассинхронизации: счётчик не может разойтись с корзиной, потому что он не хранится отдельно.
 
### 10. Почему при полной перерисовке теряется фокус и как это решает обновление по ключу? Какая аналогия у этого в React?
 
При полной перерисовке старое поле ввода заменяется новым элементом, а фокус был у старого, поэтому он пропадает.
 
При обновлении по ключу у каждой карточки есть ключ (id) и Map id → элемент. Лишние элементы удаляются, новые создаются, существующие обновляются только при изменении. Поле поиска не заменяется, поэтому фокус и текст остаются.
 
В React это атрибут `key` в списках.
