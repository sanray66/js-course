# Контрольные вопросы

### 1. Почему new Array(3) и [3] дают разные массивы?

new Array(3) создаёт массив длиной 3 с пустыми ячейками, но без значений.

[3] создаёт массив с одним элементом — числом 3.

### 2. Чем поверхностная копия массива отличается от глубокой? Когда это важно?

Поверхностная копия создаёт новый массив, но вложенные объекты остаются общими ссылками.

Глубокая копия создаёт новые копии вложенных объектов.

Это важно, когда нужно изменять копию, не затрагивая исходные данные.

### 3. Чем map отличается от forEach и от filter?
- map() создаёт новый массив, преобразуя каждый элемент.
- forEach() просто выполняет функцию для каждого элемента и не создаёт новый массив.
- filter() создаёт новый массив только с элементами, прошедшими условие.
### 4. Что произойдёт, если не передать начальное значение в reduce?

Первый элемент массива станет начальным значением аккумулятора, а перебор начнётся со второго элемента.

Если массив пустой, возникнет ошибка TypeError.

### 5. Почему [10, 9, 1, 100].sort() сортирует числа неправильно?

Потому что по умолчанию sort() сравнивает элементы как строки, а не как числа.

Для правильной сортировки чисел нужно использовать функцию сравнения:

arr.sort((a, b) => a - b).

### 6. Назовите три метода, изменяющих массив, и их неизменяющие аналоги.
- push() — concat().
- splice() — toSpliced().
- sort() — toSorted().
Изменяющие методы меняют исходный массив, а неизменяющие возвращают новый.

### 7. Почему строки в JavaScript неизменяемы и как у примитива могут быть методы?

Строки неизменяемы, потому что после создания их содержимое нельзя изменить.

Методы доступны благодаря автоматической временной обёртке примитива в объект String. Поэтому можно вызывать методы вроде toUpperCase().

### 8. Что такое XSS и как его предотвратить при выводе данных через innerHTML?

XSS — это уязвимость, при которой злоумышленник может внедрить вредоносный код на страницу через пользовательские данные.

Для защиты нужно экранировать HTML-символы или использовать textContent вместо innerHTML, если выводится обычный текст.

### 9. Почему test с флагом g может давать разные ответы для одной строки?

Потому что регулярное выражение с флагом g запоминает позицию последнего совпадения в свойстве lastIndex.

При каждом вызове test() поиск продолжается с этой позиции, поэтому результаты могут чередоваться.

### 10. Чем жадный квантификатор отличается от ленивого?

Жадный квантификатор старается захватить максимально возможное количество символов.

Ленивый старается захватить минимальное количество символов, необходимое для совпадения.

Например, .* — жадный, а .*? — ленивый.
