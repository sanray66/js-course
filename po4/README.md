### 1. Что выведет typeof для класса и почему?

typeof для класса вернёт "function", потому что класс в JavaScript является специальным видом функции-конструктора.

### 2. Где хранятся методы класса: в каждом экземпляре или в одном месте? Как это проверить?

Методы класса хранятся в прототипе класса (Class.prototype), а не в каждом экземпляре.

Проверить это можно через Object.getPrototypeOf(): у экземпляров одного класса будет общий прототип.

### 3. Почему метод, сохранённый в переменную, теряет this? Как это исправить?

this зависит от способа вызова функции.

При сохранении метода в отдельную переменную связь с объектом теряется. Исправить это можно с помощью bind(), который привязывает this к нужному объекту.

### 4. Чем приватное поле #items отличается от обычного свойства _items?

#items — настоящее приватное поле, доступное только внутри класса.

_items — обычное свойство. Подчёркивание лишь условно обозначает, что оно предназначено для внутреннего использования, но обратиться к нему снаружи можно.

### 5. Почему обращение к приватному полю снаружи класса это синтаксическая ошибка, а не ошибка выполнения?

Потому что JavaScript проверяет правильность обращения к приватным полям ещё на этапе разбора кода. Если обратиться к #items за пределами класса, код не пройдёт синтаксическую проверку.

### 6. Чем статический метод отличается от обычного? Приведите пример, когда нужен статический метод.

Статический метод принадлежит самому классу, а обычный — его экземплярам.

Например, Product.fromJSON() может создавать новый объект товара из JSON без предварительного создания экземпляра класса.

### 7. Почему вычисляемую сумму лучше делать геттером, а не хранить в поле?

Геттер вычисляет сумму на основе актуальных данных при каждом обращении.

Если хранить сумму в отдельном поле, она может устареть после добавления или удаления товара.

### 8. Зачем в конструкторе наследника вызывать super() и почему до этого нельзя использовать this?

super() вызывает конструктор родительского класса и инициализирует родительскую часть объекта.

До вызова super() нельзя использовать this, потому что объект наследника ещё не инициализирован.

### 9. Как движок находит метод при вызове monitor.describe()?

Сначала JavaScript ищет метод в самом объекте monitor.

Если не находит, проверяет его прототип, затем следующий прототип по цепочке и так далее, пока не найдёт метод или не дойдёт до null.

### 10. Почему в CartView состояние нельзя менять напрямую, а только через setState?

Потому что setState() централизованно обновляет состояние и вызывает render().
